================================================================================
  NEBULAPROXY — ROTATING PROXY PORTAL
  DEPLOYMENT GUIDE  (v1.3.0)
  Free / Low-cost Hosting — No Credit Card Required
================================================================================

This guide explains how to deploy the NebulaProxy rotating-proxy portal to
different hosting platforms. It is written especially for users who DO NOT
have a credit card (and therefore cannot create an Oracle Cloud / Google Cloud /
AWS account, all of which require a card for identity verification).

--------------------------------------------------------------------------------
  IMPORTANT TRUTH ABOUT "FREE + FOREVER" HOSTING
--------------------------------------------------------------------------------

Every "always free forever" cloud (Oracle Cloud Always Free, Google Cloud
Always Free, AWS Free Tier) requires a credit/debit card at sign-up for
identity verification — even though they never charge it.

A rotating proxy gateway needs TWO things that most free platforms cannot give:

  1. A REAL TCP PORT  (the gateway listens on :8000 and accepts raw
     CONNECT/HTTPS tunnels — serverless platforms like Vercel, Netlify,
     Render, Railway and Fly "functions" CANNOT do this).

  2. A PERSISTENT, ALWAYS-ON PROCESS  (the Node.js server must keep running
     24/7 — shared web hosting that only serves PHP/static files cannot run it).

So the realistic no-card options are:

  A) A REAL (Linux) VPS that you actually pay a tiny amount for (₹ / $2-5/mo).
     This is the ONLY reliable way to run a proxy gateway properly.

  B) A genuinely free/no-card VPS program (GratisVPS, VPSWala, etc.).
     These exist but have very limited resources, may be slow, may impose
     usage caps, and can disappear without notice. Good for testing, not for
     production.

  C) Run it on your OWN machine / phone (free, but only online while your
     device is on and your IP/ports are reachable). See Section 6.

  D) A free Oracle/Google tier — NOT possible for you without a card.

Below, each option is explained in detail with step-by-step instructions.

================================================================================
  SECTION 1 — ExaCloud  (€ / paid VPS, but affordable)
================================================================================

"ExaCloud" (exacloud.net) is a Spanish cloud/VPS provider. Their Cloud VPS
plans start around €29.95/month — NOT free, and a bit expensive for personal
use. There are also other companies using the "ExaCloud/Excloud" name
(e.g. excloud.tech in Asia). Verify the exact provider before paying.

If you do use ExaCloud (or any real VPS), the setup steps are the SAME as any
Ubuntu VPS — see Section 3 "Generic Ubuntu/Linux VPS Setup".

  - Pick a Linux VPS running Ubuntu 22.04 / 24.04 (LTS).
  - You need ROOT SSH access.
  - Open the required ports (3000 web UI, 8000 proxy gateway).
  - Follow Section 3 exactly.

================================================================================
  SECTION 2 — Free / No-Credit-Card VPS Providers
================================================================================

These are community-known "free VPS" programs that do NOT ask for a card.
They are limited and NOT guaranteed to stay online forever — treat them as
testing/demo hosts, not production.

  1) GratisVPS  (gratisvps.org area / search "GratisVPS free VPS")
     - 1 vCPU, ~1 GB RAM, NVMe, Linux (Ubuntu/Debian).
     - No credit card. Green Tier-3 datacenter.
     - Best for: learning / testing the portal.

  2) VPSWala  (search "VPSWala free VPS")
     - Another no-card free VPS with small specs.

  3) Alibaba Cloud Free Trial  (alibabacloud.com)
     - Free trial credits; some regions allow sign-up with less strict card
       checks, but most still request a card. Verify before investing time.

  4) Kamatera / Ultahost / VPSServer "free trial VPS"
     - These are FREE TRIALS (usually 30 days), often no card for the trial.
     - Good for a short demos, not permanent.

  IMPORTANT: On any of these, you must still be able to:
    - get SSH/root access,
    - open TCP ports 3000 and 8000 in their firewall/console,
    - install Node.js (v18+) and run `npm install`.

================================================================================
  SECTION 3 — Generic Ubuntu / Linux VPS Setup (works everywhere)
================================================================================

Use this whenever you have any Linux VPS with root SSH access.

  STEP 0 — Connect
    ssh root@YOUR_SERVER_IP

  STEP 1 — Install Node.js 20 (LTS)
    curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
    sudo apt-get install -y nodejs git
    node -v    # should print v20.x

  STEP 2 — Install PM2 (keeps the app running 24/7 & auto-restarts)
    sudo npm install -g pm2

  STEP 3 — Upload the project
    Option A (from your PC): use scp/sftp to upload nebulaproxy-portal.zip,
      then:  mkdir -p /opt/nebulaproxy && cd /opt/nebulaproxy
             apt-get install -y unzip
             unzip nebulaproxy-portal.zip
    Option B (from GitHub): if you pushed it to a repo:
             git clone YOUR_REPO_URL /opt/nebulaproxy

  STEP 4 — Install dependencies
    cd /opt/nebulaproxy
    npm install --production

  STEP 5 — Configure .env (edit with nano/vi)
    nano .env
    Make sure PORT=3000, GATEWAY_PORT=8000 are set, and keep your
    ADMIN_PASSWORD_HASH / JWT_SECRET / API_KEY / GATEWAY_USER / GATEWAY_PASS.

  STEP 6 — Open firewall ports
    sudo ufw allow 22     # SSH (keep this!)
    sudo ufw allow 3000   # Web UI / Admin panel
    sudo ufw allow 8000   # Proxy gateway
    sudo ufw enable

    (If your provider's cloud console has its own firewall/security group,
     also open 3000 & 8000 TCP there — this is the #1 cause of "can't connect".)

  STEP 7 — Start with PM2
    cd /opt/nebulaproxy
    pm2 start server.js --name nebulaproxy
    pm2 save
    pm2 startup          # follow the printed command so it survives reboots

  STEP 8 — Verify
    Open  http://YOUR_SERVER_IP:3000   in your browser → login to admin panel.
    Gateway proxy URL for your clients:
      http://GATEWAY_USER:GATEWAY_PASS@YOUR_SERVER_IP:8000

  STEP 9 — (Optional) Point a domain / enable HTTPS
    Use a free reverse proxy such as Caddy or Nginx + Let's Encrypt.
    Caddy example (simplest):
      sudo apt-get install -y caddy
      Caddyfile:
        yourdomain.com {
          reverse_proxy localhost:3000
        }
    (For the raw :8000 gateway, TLS is optional — clients generally use it as
     an HTTP/SOCKS proxy, not a website.)

================================================================================
  SECTION 4 — Troubleshooting (common issues)
================================================================================

  "Can't reach server from outside"       → open ports in BATH ufw AND the
                                            cloud console/security group.

  "Port already in use"                         → sudo lsof -i :3000  /  :8000 ;
                                                kill the conflicting process.

  "npm install fails"              " should ensure Node >= 18: node -v

  "Proxies show unhealthy" should → click "Run Health Check" in the
                                            admin panel. Proxies degrade over
                                            time; re-check after deploy.

  "Gateway returns 407" → wrong GATEWAY_USER/GATEWAY_PASS in client config.

================================================================================
  SECTION 5 — How to give clients the rotating proxy
===============================================================================

  Gateway endpoint (HTTP proxy):
    http://GATEWAY_USER:GATEWAY_PASS@GATEWAY_HOST:8000

  In tools like cURL:
    curl -x http://GATEWAY_USER:GATEWAY_PASS@GATEWAY_HOST:8000 https://api.ipify.org

  Rotation: every new connection gets a DIFFERENT exit IP (no back-to-back
  repeats). In the Admin → Rotation & Settings tab you can choose:
    • Round Robin      — cycles each healthy node in order
    • Random           — random node (avoids immediate repeat)
    • Unique IP Cycle  — NEVER repeats the same IP twice in a row (recommended)
    • Least Used      — favors idle nodes
    • Best Latency     — always the fastest node
    • Sticky Session   — pin a client to one node via X-Session-Id header

================================================================================
  SECTION 6 — Run it on your own machine (100% free, no card)
================================================================================

  If you just want to test or use it privately, run it locally:

    On Windows/Mac/Linux (you own the machine):
      npm install
      npm start
      → open http://localhost:3000

    On Android (e.g. Termux — your setup):
      pkg install nodejs
      cd /path/to/rotating-proxy-portal
      npm install
      npm start
      → open http://127.0.0.1:3000

  Limitation: it is only reachable while your device is on, and only from
  your own network (or via a tunnel like cloudflared/ngrok if you open it up).

  To expose it publicly for free (no card), use a tunnel:
    ngrok http 3000        → gives a public https URL to the admin panel
    cloudflared tunnel     → Cloudflare's free tunnel (needs a free CF account)

  NOTE: Tunnels expose the WEB UI fine, but the raw proxy gateway (:8000) is
  harder to expose through HTTP-only tunnels. For a fully public gateway,
  prefer a real VPS (Section 3).

================================================================================
  SECTION 7 — Honest recommendation for you
================================================================================

  Since you do not have a credit card:

    • For a REAL, always-on public proxy portal → the cheapest reliable path is
      a low-cost real VPS (~$2–5/month). Look for:
        - Hetzner Cloud (ARM/AMD ~€3.29/mo, but needs a card)
        - Contabo, Racknerd, Hostinger VPS (some accept PayPal/other payment)
        - Any regional provider in Bangladesh/India accepting local payment
          (e.g. bKash/Nagad) — search "cheap VPS bKash payment".

    • For FREE testing / demos → GratisVPS or VPSWala (Section 2).

    • For private/development use → run on your own PC/phone + a tunnel
      (Section 6).

  A proxy gateway is a real network service, not a static website — this is
  why there is no truly-free, no-card, forever, public-port option that is
  reliable. The moment a FREE host appears, it gets abused and shut down.
