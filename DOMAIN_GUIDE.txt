================================================================================
NEBULAPROXY — DOMAIN & FREE DOMAIN GUIDE
How to add a custom domain (or get a free one) after cloud deployment
================================================================================

You've deployed NebulaProxy to a VPS, and you have a public IP like
185.199.108.153. Instead of visiting http://185.199.108.153:3000, you want
a clean address like https://proxy.yourname.com.

This guide covers, in order:
  1. What a domain / DNS actually does (so you understand each step)
  2. OPTION A — Get a FREE domain (no card needed)
  3. OPTION B — Buy a cheap domain (~$0.99–$12/yr)
  4. Connect the domain to your server (DNS + reverse proxy)
  5. Free HTTPS with SSL (Let's Encrypt)
  6. Full worked example (Caddy — easiest)

--------------------------------------------------------------------------------
1. WHAT A DOMAIN / DNS ACTUALLY DOES
--------------------------------------------------------------------------------
A domain (e.g. myproxy.xyz) is just a friendly name. Behind it are DNS records
that point to your server's public IPv4 address (an "A" record).

  myproxy.xyz   -->  A record  -->  185.199.108.153   (your VPS)

DNS is free; it is built into every domain registrar and every VPS. The only
thing that normally costs money is REGISTERING the name itself (the yearly fee).

Two things to know:
  - A RECORD      = points a name to an IP address (this is what you need)
  - CNAME RECORD  = points a name to ANOTHER name (used for subdomains/aliases)
  - SUBDOMAIN     = something before the main name, e.g. proxy.myproxy.xyz

--------------------------------------------------------------------------------
2. OPTION A — GET A FREE DOMAIN (no credit card)
--------------------------------------------------------------------------------
These give you a real, usable domain (or subdomain) for FREE. Perfect for a
personal proxy gateway.

(a) Free subdomains (fastest, zero setup cost):
  - freedns.afraid.org  — free subdomains under thousands of domains
                          (e.g. yourname.mooo.com), fully configurable A records.
  - noip.com            — free hostnames like yourname.ddns.net (free tier
                          requires manual confirmation every ~30 days).
  - duckdns.org         — free yourname.duckdns.org, one-click, great API for
                          dynamic IP updates. Only needs a GitHub/Twitter login.

(b) 100% free real TLDs (a full domain you own, no card):
  - Freenom            — historically offered .tk/.ml/.ga/.cf/.gq for free.
                        NOTE: Freenom has been unreliable/down since ~2023.
                        Try it, but do not depend on it.
  - eu.org             — free "yourname.eu.org" registration (manual approval,
                        usually a few days, but genuinely free and permanent).
  - js.org             — free subdomains for open-source/GitHub projects.
  - is-a.dev           — free subdomains for developers (via GitHub PR).

(c) Free subdomains from hosting/CI services:
  - GitHub Pages       — username.github.io
  - Netlify / Vercel   — project-name.netlify.app / .vercel.app
  (These are for static sites only; they CANNOT host the proxy gateway itself,
   but can host a landing/status page separately.)

RECOMMENDATION: For a self-hosted proxy gateway, use DuckDNS or FreeDNS first
(it takes 2 minutes and you get a working HTTPS-capable name immediately).
Later, if you want a clean .com/.xyz, buy one (~$1–$3).

--------------------------------------------------------------------------------
3. OPTION B — BUY A CHEAP DOMAIN (~$0.99–$12/yr)
--------------------------------------------------------------------------------
If you want a professional domain you fully own. These registrars are cheap and
many don't strictly require a credit card (some accept PayPal, bKash, etc.):

  - Namecheap  (.xyz promo ~$0.99 first year, .com ~$5.98+)
  - Porkbun    (very cheap renewals, .xyz ~$1–$2)
  - Cloudflare Registrar (at-cost pricing, no markup)
  - Dinahosting / Hostinger / GoDaddy (often have 1st-year deals)

Bangladesh-friendly payment note: If you don't have a card, check providers that
accept bKash/Nagad or internet banking, or buy a virtual card. Some users also
use PayPal balance. Porkbun and Namecheap accept PayPal.

--------------------------------------------------------------------------------
4. CONNECT YOUR DOMAIN TO YOUR SERVER
--------------------------------------------------------------------------------
Steps (same for free subdomain or a bought domain):

STEP 1 — Get your server's public IPv4 address:
    curl -s ifconfig.me        # on the VPS, prints its public IP
  Example output: 185.199.108.153

STEP 2 — Add an A record at your DNS provider:
    Type:   A
    Name:   @            (or the subdomain part, e.g. "proxy")
    Value:  185.199.108.153
    TTL:    Auto / 300

  - If using a subdomain like "proxy", the Name field is "proxy" and it becomes
    proxy.yourdomain.xyz.
  - If you want the bare domain to work too, add a second A record with Name "@".

STEP 3 — Wait for DNS to propagate (usually 1–10 minutes, sometimes up to 24h):
    nslookup yourdomain.xyz

STEP 4 — Point the domain to the running app using a reverse proxy (Section 6).

--------------------------------------------------------------------------------
5. FREE HTTPS (SSL) WITH LET'S ENCRYPT
--------------------------------------------------------------------------------
Browsers/clients will warn on plain HTTP. To get a FREE, auto-renewing
certificate (https://), use one of these reverse proxies which handle the
certificate for you automatically:

  - Caddy      (simplest — 2 lines of config, auto-HTTPS built in)
  - Nginx      (industry standard, needs certbot for SSL)
  - Traefik    (Docker-native, auto-SSL)

All three are free and open source. Caddy is recommended if you are new.

--------------------------------------------------------------------------------
6. FULL WORKED EXAMPLE (CADDY — EASIEST)
--------------------------------------------------------------------------------
Install Caddy on your Ubuntu/Debian VPS:

    sudo apt update
    sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
    curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-architecture.gpg
    curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
    sudo apt update
    sudo apt install caddy

Create a Caddyfile:
    sudo nano /etc/caddy/Caddyfile

content:
    proxy.yourdomain.com {
        reverse_proxy localhost:3000
    }

Restart Caddy:
    sudo systemctl restart caddy

Now you can visit https://proxy.yourdomain.com — free https certificate
automatically issued by Let's Encrypt.

-------------------------------------------------------------------------------
7. NOTE ON THE RAW GATEWAY PORT :8000
--------------------------------------------------------------------------------
The domain above covers the web portal (:3000). Your rotating proxy gateway
(:8000) is a raw TCP proxy — clients connect to it directly by IP/
port, not through a domain. It is Normal to keep the gateway on a raw
public IP!  (proxy clients do not need HTTPS on a tunnel).
